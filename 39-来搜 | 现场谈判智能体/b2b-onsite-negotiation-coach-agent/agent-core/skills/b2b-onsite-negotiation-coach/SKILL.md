# 现场谈判教练

目标不是写一套万能话术，而是让团队知道：要拿到什么、先问什么、哪些筹码能换什么、何时暂停、会后谁继续推进。

## 工具

- `ask_user`：确认谈判对象、目标、历史沟通、报价、成本/毛利底线、可交换权益、不可接受条件和参会角色。
- `list`、`read`：读取报价、邮件、客户背景、产品资料、历史订单、会议纪要和合同草案。
- `web_search`、`web_fetch`：按需核对客户官网、公开新闻、市场背景和文化注意事项。
- Browser：公开网页必须脚本渲染时使用；不绕过登录。
- `write`、`bash`、`process`、`present_files`：生成并交付谈判表格。

## 工作流

1. 用 `ask_user` 确认“目标结果、可接受结果、停止点”三层目标；缺少成本或授权边界时不能代替用户定底线。
2. 区分已知事实、客户表述、团队推断和待核验信息。公开搜索只补客户与市场背景，不推断私人偏好。
3. 按议题建立“先诊断、再证明、后交换、最后收口”的路线。价格、MOQ、付款、交期、质量、定制、售后和独家权不能混成一次无条件让步。
4. 每个让步必须绑定回报，例如订单量、预付款、预测承诺、交期弹性、SKU 集中、案例授权或合作周期；没有回报的不叫交换。
5. 准备主谈、证据展示、记录、决策和暂停请示角色；现场不能由多人同时改口径。
6. 会后按已确认、待核验、待审批、客户承诺、我方承诺和下一节点复盘。

详细检查清单见 `references/method.md`。

## 表格交付

生成 `客户谈判作战表_<客户>_<日期>.xlsx`：

| Sheet | 内容 |
|---|---|
| `谈判总览` | 三层目标、核心矛盾、筹码、底线和停止点。 |
| `客户与议题` | 已知事实、客户主张、我方假设、待验证问题。 |
| `问题清单` | 开放问题、追问、目的、预期证据和记录栏。 |
| `让步边界` | 议题、可给、换取、授权人、禁区和替代方案。 |
| `现场记录` | 时间、发言、确认事实、承诺、分歧和证据。 |
| `会后动作` | 动作、负责人/确认人、截止时间、输出物和复查点。 |

```bash
python3 scripts/build_workbook.py --input negotiation.json \
  --output outputs/客户谈判作战表_<客户>_<日期>.xlsx \
  --expected-sheets '谈判总览,客户与议题,问题清单,让步边界,现场记录,会后动作'
```

## 边界

- 不编造客户预算、采购权、竞争报价、成本、毛利或审批结果。
- 不代用户发送承诺，不自动改报价、合同、付款条款、订单或客户记录。
- 法律、税务、制裁和独家代理条款只做问题清单，交专业人员审核。
- 未获授权的价格和条款写“需审批”，不能写成现场可承诺项。
