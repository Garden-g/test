# AI 产品设计

从真实客户问题出发，把模糊创意收敛成能交给产品、工程和销售共同评审的设计 brief。

## 工作流

1. 用 `ask_user` 确认产品类别、目标买家、使用场景、必须保留项、成本区间、制造能力、认证市场和本次要解决的问题。
2. 用 `read` 读取现有产品、投诉、询盘、竞品记录和工艺资料；用 `web_search`、`web_fetch` 查公开买家需求、同类结构与法规线索，保留来源和日期。
3. 建立事实账本：用户确认、资料证据、公开事实、团队假设、待验证、禁止承诺。不要把趋势或竞品功能直接写成自家能力。
4. 提出最多 3 个概念方向。每个方向写目标客户、核心任务、功能/结构、差异点、制造影响、成本风险、合规风险和验证方法。
5. 用价值、可制造性、证据强度、差异化和风险做取舍，给出推荐方向与暂不做项。
6. 交付 `AI产品设计Brief_<产品>_<日期>.xlsx`，包含 `设计结论`、`客户问题`、`概念方案`、`需求与约束`、`验证计划`。

## 概念图

用户只要方案时不生图。用户明确要求概念图且已确认方向后：没有参考产品时可用 `image_generate` 生成并标记“概念稿”；有真实产品或结构参考时先用 `see_image`，再用带 `reference_images` 的 `image_edit`。生成前说明输出数量、允许改变项和不会自动发布的边界。

## 边界

- 不编造材料性能、专利状态、认证、成本、可制造性或市场销量。
- 概念图不能作为工程图、合规证明或量产承诺。
- 涉及人体安全、电气、医疗、儿童、食品接触或受监管用途时，把专业评审列为上线前置条件。
- 不自动创建商品、上传图片、修改目录或对客户发送承诺。
