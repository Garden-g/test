# 开发信方法

本参考提炼本地开发信材料的通用方法，不复制其中公司、产品、客户或案例文本。

## 首封检查

- 与收件人的业务有关，而不是只介绍自己。
- 一个可验证的价值点，一个行动目标。
- 个性化来自可追溯公开事实。
- 没有未知发件人的大附件、过多链接或夸张格式。
- 签名包含真实姓名、职位、公司和可核验联系方式。

## 跟进序列

1. 首封：相关问题与低门槛 CTA。
2. 跟进一：补充一个具体产品/场景价值或简短证据。
3. 跟进二：回答可能顾虑，提供样品、规格或简短方案入口。
4. 最后触达：礼貌确认时机，不制造虚假紧迫。

每一步都应设置停止条件：明确拒绝、地址无效、不再相关或合规要求停止。

## 禁用

虚假社会证明、无法核验的百分比、冒充熟人、误导性 Re/Fwd、批量模板中的称呼错误、多个冲突 CTA。
