# 高回复开发信

开发信要让收件人快速理解“为什么是我、你能提供什么可信价值、我只需要回复什么”。不使用虚假客户案例、夸张承诺或模板式长篇公司介绍。

## 工具

- `ask_user`：确认客户/客群、产品、目标市场、可信卖点、案例/认证、语气、邮件阶段和唯一 CTA。
- `list`、`read`：读取客户资料、产品资料、历史邮件、报价和品牌语气。
- `web_search`、`web_fetch`：按需核对客户官网、公开新闻、产品线、渠道和联系人角色。
- Browser：核对脚本渲染的公开页面，不绕过登录。
- `write`、`bash`、`process`、`present_files`：生成邮件草稿与发送计划表格。

## 写作流程

1. 建立证据表：客户公开事实、我方可证明事实、双方可能匹配、仍需核验。没有证据的个性化句子不用。
2. 每封只选一个主问题或机会，结构为：自然称呼 → 个性化钩子 → 价值与证据 → 一个低门槛 CTA → 签名。
3. 首封默认保持简短、可扫读、移动端友好；具体长度由场景决定，不机械套字数。
4. 主题行具体、自然、不夸张；避免全大写、虚假紧迫、过度促销和多个感叹号。
5. 一个邮件只保留一个 CTA。首次接触优先询问兴趣、需求或是否适合简短沟通，不同时要求回复、下载、加好友和开会。
6. 跟进序列每封提供新价值或新证据；不能只是“checking in”。沉睡客户先理解停滞原因，再决定是否推进订单。
7. 输出发送前检查：称呼、公司、产品、数字、附件、链接、语法、退订/合规和发件人签名。

方法见 `references/method.md`。

## 交付

聊天中先给可直接审阅的英文邮件草稿；批量或序列任务同时生成 `开发信计划_<客群>_<日期>.xlsx`：

| Sheet | 内容 |
|---|---|
| `邮件草稿` | 客户、阶段、主题、正文、CTA、语气和版本。 |
| `个性化证据` | 客户事实、来源、可用钩子、证据强度和禁用推断。 |
| `价值映射` | 客户问题、我方价值、证明材料和可接受表述。 |
| `跟进序列` | 节点、目的、新价值、草稿、停止条件。 |
| `发送前检查` | 称呼、数字、链接、附件、签名、合规和人工确认。 |

```bash
python3 scripts/build_workbook.py --input cold_email.json \
  --output outputs/开发信计划_<客群>_<日期>.xlsx \
  --expected-sheets '邮件草稿,个性化证据,价值映射,跟进序列,发送前检查'
```

## 边界

- 不自动发送邮件、创建群发任务、抓取私人邮箱或猜邮箱格式。
- 不保证打开率、回复率或成交率；知识材料中的效果数字不能当承诺。
- 不编造客户动态、合作品牌、认证、案例、价格优势或库存。
- 发送前必须由用户确认收件人、主题、正文、附件、链接和当地隐私/营销合规。
