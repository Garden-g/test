# 详情页策划与生成

## 目标

根据产品词、产品描述或产品图识别产品与行业，补齐详情页真正需要的产品、定制、工厂和信任信息，再输出一套不超过 8 张的独立竖版详情图 Markdown 方案；用户确认后可逐张生成图片。

用户只要方案时不生图。用户明确要求生成时，先确认方案、图片数量和拟调用次数，再调用 Accio 内置生图工具；不自动上传素材、创建页面或发布页面。

## 职责边界

- 六张 `1:1` 商品图：转 `alibaba-b2b-image-set-generator`。
- 单张图改色、Logo、翻译、模特场景、短视频或视觉合规：转 `alibaba-visual-asset-director`。
- 旺铺模板、活动页、页面预览和发布：转 `alibaba-store-page-campaign-planner`。
- 本 skill 负责：产品详情页需要哪些竖版图片、每张解决什么采购问题、怎么构图、写什么、需要哪些真实素材。

## 工具地图

| 工具 | 何时使用 | 核心要求 |
|---|---|---|
| `see_image` | 用户上传产品图或提供图片 URL | 先识别产品身份、可见结构、材质颜色、标签、品牌/水印/联系方式和明显风险；不可从图片猜认证或性能数字。 |
| `web_search` | 产品关键词基本明确后 | 搜索 B2B 买家关注点、采购参数和常见应用；只形成行业假设，不证明用户产品具备某项能力。 |
| `ask_user` | 产品身份不清或关键信息会改变方案时 | 每次只问一个主题，提供 2-4 个可点击选项；最多连续 3 轮，已有信息不重复问。 |
| `image_edit` | 用户提供产品图、商品参考图或上一张生成结果时 | 把参考图放入 `reference_images`，基于同一产品做场景、卖点、细节、定制、流程、排版和竖版详情图；这是保持产品一致性的主工具。 |
| `image_generate` | 用户没有任何参考图时 | 纯文生图；若要生成一套同款产品详情图，先生成并确认 1 张主参考，再把该结果放入后续 `image_edit.reference_images`。 |

`see_image`、`web_search`、`ask_user`、`image_generate` 和 `image_edit` 属于当前 Accio 内置能力。不要把它们写成 Alibaba MCP 或店铺数据工具，也不要自行增加图片工具之外的虚构前置步骤。

## 工作流程

### 1. 识别输入

先判断用户提供的是：

- 产品关键词或名称。
- 产品描述、规格或卖点。
- 单张或多张产品图片。
- 图片 URL、商品链接或混合输入。

图片输入必须先调用 `see_image`，记录：

1. 最可能的产品名称与候选行业。
2. 可见材质、颜色、结构、部件和使用线索。
3. 可见文字、Logo、水印、联系方式、认证标识和竞品包装风险。
4. 看不清或无法确认的内容。

产品身份不确定时，用 `ask_user` 给出 2-4 个候选产品名，不要自行选定。多款产品同时出现时，确认是做单品详情页还是产品集合页。

只有关键词时，先判断行业，不要假装知道型号、尺寸、性能、认证、MOQ、交期、产能或工厂能力。

### 2. 搜索采购关注点

产品关键词明确后，用 `web_search` 搜索 2-4 组英文 B2B 查询，例如：

- `<product> B2B buyer key specifications`
- `<product> wholesale buyer concerns applications`
- `<product> OEM customization options`
- `<product> quality inspection packaging shipping`

只提取可泛化的采购问题、参数维度、应用场景和信任证据类型。竞品品牌、具体数值、认证编号、客户名称和工厂规模不得成为用户产品事实。

### 3. 建立事实账本

把所有信息分成五类：

| 状态 | 含义 | 在方案中的写法 |
|---|---|---|
| 用户已确认 | 用户明确提供的产品事实 | 可以进入文案和画面。 |
| 图片可见 | `see_image` 能直接观察到 | 只描述可见事实，不扩大结论。 |
| 行业假设 | 来自搜索的常见采购关注点 | 写成“建议核实/候选模块”。 |
| 待确认 | 缺规格、证书、授权或后台事实 | 保留模块，但用占位字段和补料要求。 |
| 禁止上线 | 无授权 Logo、虚假评价、假证书、无法证明的性能 | 从公开文案和生成 Prompt 中删除。 |

### 4. 用 `ask_user` 补最关键的信息

产品已经能识别时，不要把所有字段一次性扔给用户。先读取 [detail-page-module-guide.md](references/detail-page-module-guide.md)，根据行业选择最多 3 个最有价值的问题。

优先顺序：

1. 目标买家、国家/语言和主要应用。
2. 会改变详情页叙事的核心功能或参数。
3. 已有的定制、工厂、证书、检测、客户或品牌合作证据。

例如识别为电子设备时，可询问主要特殊功能方向：连接方式与接口、供电与续航、软件/APP、环境适应性、安全与认证。只有用户确认并有证据时，才能写具体功能和参数。

如果用户不回答，继续生成方案，但所有缺失事实标为 `待确认`，不得卡死。

### 5. 规划多张竖版详情图

默认规划 6-8 张独立图片，任何情况下默认不得超过 8 张；只有用户明确要求更多图片时，才可以突破上限。用户需求超过 8 个模块但没有要求增加张数时，把相近内容合并到同一张竖图。

必须检查以下维度；没有证据或不适用时也要在方案里说明，不要静默遗漏：

- 2-4 张产品详细介绍：定位、核心卖点、功能、结构、应用、对比或使用方式。
- OEM 工厂海报：服务范围、身份定位、可验证的生产或供货能力。
- 品牌合作、客户好评、证书、检测报告：只使用真实授权和证据。
- 产品集合展示：实际存在的款式、型号、尺寸、颜色或组合。
- 定制服务：Logo、尺寸/形状、材质/颜色、包装；未确认能力不得写“支持”。
- 合作流程、产品参数、产品细节。
- 公司介绍、团队/展会、生产流程、包装物流、FAQ 和询盘引导。

阅读 [detail-page-module-guide.md](references/detail-page-module-guide.md)，从模块库选择并合并为最多 8 张，按行业调整顺序，不要把所有产品套同一个模板。

### 6. 选择竖版比例

- `9:16`：默认用于主视觉、应用场景、OEM 工厂、生产流程、公司团队和品牌故事等叙事型图片。
- `4:5`：用于参数、细节、集合、定制选项、证书和 FAQ 等信息密度较高的图片。
- `3:4`：用于需要兼顾移动端阅读和模块复用的中等长度图片。

优先交付多张可替换的独立竖图，不要把整页做成一张无法局部更新的超长拼图。最终像素尺寸按当前平台和页面模板要求确认，不凭记忆写死。

每张图只解决一个主要采购问题。主标题控制为 1 行，卖点保持 2-4 条短句；详细参数放表格或标注区，不堆大段文字。

### 7. 输出 Markdown 方案

最终必须使用 Markdown，按以下结构输出：

```markdown
## 产品识别
| 项目 | 结论 | 依据 | 状态 |

## 已确认信息与待确认项
| 信息 | 当前内容 | 状态 | 缺失影响 |

## 详情页视觉策略
- 目标买家：
- 页面主线：
- 视觉风格：
- 语言：
- 计划图片数：
- 比例策略：
- 生图状态：仅方案 / 待确认生成 / 已生成

## 竖版详情图方案
| 序号 | 模块/采购问题 | 画面与构图 | 文案要点 | 比例 | reference_images/素材 | image_edit 模式 | 事实状态 |

## 信任内容与合规边界
| 模块 | 可使用证据 | 禁止内容 | 当前缺口 |

## 拍摄与设计素材清单
| 优先级 | 素材 | 用于哪些图片 | 获取方式 |

## 下一步
<告诉用户最少补哪 3 项即可继续>
```

方案中的每张图都要明确：业务目的、画面主体、构图方向、建议文案、比例、`reference_images`/真实素材、`image_edit` 模式和事实状态。

### 8. 用户要求生图时先选择生成路线

用户没有明确说“生成图片、直接出图、开始生图”时，到 Markdown 方案结束，不调用任何生成工具。

#### 路线 A：用户提供了产品图

1. 用 `see_image` 识别并确认主产品图；多张产品图时，让用户选择最能代表真实商品的一张作为主参考。
2. 在调用 `image_edit` 前读取并验证每张参考图，记录真实像素、比例、格式和可见内容。远程 URL 必须可读取；本地路径必须先转换成当前工具可接受的 HTTPS 资源，不能直接传 `file://` 或本地路径。
3. 产品主视觉、卖点、场景、细节和参数图都把同一主产品图放入 `reference_images`，通过 Prompt 改变环境、构图和信息层级，保持主体外观、结构、颜色、标签和品牌一致。
4. 产品集合必须把每个真实 SKU 的图片分别放入 `reference_images`；不得用同一产品图凭空制造不存在的型号。
5. 工厂、团队、展会、证书、检测和客户证据使用各自真实素材作为参考图；不得拿商品图生成虚假工厂、证书或客户案例。
6. 如果参考图不可读、无法验证或无法转换成 `image_edit` 可接受的资源，停止并报告缺口；不得退回连续纯文生图。

每个产品相关 Prompt 都附加简短的一致性约束：

```text
Keep the product exactly unchanged — preserve geometry, color, texture, labels, and camera angle.
Only change: <本张允许变化的背景、排版、标注或场景>.
Do not redraw, simplify, or invent any product detail.
```

#### 路线 B：用户只有产品词

1. 先输出 Markdown 方案，并优先请用户补一张真实产品参考图。
2. 用户没有实拍图但明确接受“概念稿”时，才调用一次 `image_generate` 生成主产品参考图。
3. 把主参考图展示给用户确认；未确认前不继续生成详情图。
4. 把已确认主参考图加入后续所有产品相关 `image_edit.reference_images`。当前结果无法作为参考图传入 `image_edit` 时停止，并要求用户提供可用产品图。
5. 不得对同一个产品连续调用 `image_generate` 6-8 次来拼详情页，因为这会导致产品结构、颜色和外观漂移。

### 9. 执行图生图链

用户要求实际生成时：

1. 先确认最终图片数量；默认不超过 8 张，用户明确要求更多时才增加。
2. 先检查当前 `image_edit` schema。若支持 `auto_generation`，优先使用；否则标准场景用 `simple_generation`，多区域卖点海报、参数布局、流程图等密集版式用 `complex_generation`。不要在没查 schema 时猜 `task_type`。
3. 为每张图整理独立英文图生图 Prompt，明确需要保留的产品结构、颜色、比例、Logo、部件和禁止改变项，再写业务目的、场景、构图、已确认卖点、可见英文短文案和竖版比例。
4. 向用户展示：每张图的 `reference_images`、`task_type`、图片数量、目标比例、拟调用次数，以及不会自动上传/发布的边界。若当前运行环境主动返回额度或计费信息，只按真实返回转述，不额外编造或调用不存在的查询工具。
5. 用户针对本次生成明确确认后，为每张计划输出调用一次 `image_edit`；所有产品相关输出都必须带主产品参考图，不得改成纯文本 `image_generate`。
6. 用户明确要求 `9:16`、`4:5` 或 `3:4` 时，按当前 schema 传入受支持的 `aspect_ratio`；如支持 `auto_generation` 和 `size`，按用户目标尺寸传入，不要先生成错误比例再重复猜测。
7. 每张结果记录对应序号、用途、`reference_images`、`task_type`、最终 Prompt 和真实调用状态；单张失败只重试该张一次。
8. 权限不可用、参考图不合格或工具未返回时，停止生成并交付 Markdown 方案、独立 Prompts 和阻断原因，不声称图片已生成。

生成质量要求：

- 画面必须是可独立使用的详情页竖图，而不是多个小面板拼成的预览。
- 产品相关图片必须保持主参考图中的主体结构、轮廓、部件、颜色和品牌一致；不允许每张重新发明一个产品。
- 每张最多 1 个主标题、2-4 个短卖点；避免长段文字和乱码风险。
- 不生成假 Logo、假客户评价、假证书、假检测报告、假工厂、假参数或未确认的定制能力。
- 同一套图片保持产品外观、颜色、品牌、字体层级和视觉系统一致。

### 10. 修改单张图片

用户说“第 N 张改成……”时：

1. 锁定对应图片和原 Prompt。
2. 展示当前结果图、修改内容、拟用 `image_edit` 模式、预计调用次数和影响。
3. 用户确认本次编辑后，把当前结果图和必要的原产品图放入 `reference_images`，调用 `image_edit`。
4. 只输出修改后的第 N 张及更新 Prompt，其他图片保持不变。

## 信任内容红线

- 品牌合作：只有获得授权且可公开展示时才放品牌 Logo。
- 客户好评：必须来自真实客户记录；不得生成假姓名、假头像、假国旗、假五星和假引语。
- 证书与检测：必须对应当前产品、型号和有效范围；不得制作类似认证徽章。
- OEM 工厂：只写已确认的服务和生产事实；通用工厂图库不能证明用户拥有工厂。
- 公司、团队与展会：使用真实照片和身份；不得把素材库人物包装成用户团队。
- 参数、性能与物流：必须有规格、测试或政策依据；不得从竞品页面照抄。

## 质量闸

交付前检查：

- 是否先识别产品，再规划详情页。
- 图片输入是否真实调用 `see_image`。
- 是否根据行业提出了针对性问题，而不是固定问卷。
- 是否覆盖用户要求的全部详情页维度。
- 默认方案是否不超过 8 张；超过时用户是否明确要求。
- 是否以竖版图片为主，并按内容选择 `9:16`、`4:5` 或 `3:4`。
- 是否明确区分已确认、图片可见、行业假设和待确认。
- 是否没有虚构 OEM、客户评价、品牌合作、证书、检测、工厂或参数。
- 用户只要方案时是否没有调用生图工具。
- 有产品参考图时是否使用 `image_edit.reference_images`，并用同一主参考保持产品一致性。
- 只有纯关键词且用户接受概念稿时，是否只用 `image_generate` 生成一张主参考，而不是连续生成整套。
- 用户要求生图时是否检查真实 schema、展示调用影响、获得确认，再用 `image_edit` 执行图生图。
- 是否没有把提交任务冒充成生成成功，也没有自动上传或发布页面。
