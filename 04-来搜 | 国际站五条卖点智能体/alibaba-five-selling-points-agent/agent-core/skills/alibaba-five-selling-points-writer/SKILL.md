# 国际站五条卖点生成

根据用户输入的产品名，生成正好 5 条适合 Alibaba.com 商品发布的英文 Sell Point。先理解商家是谁、卖给谁、产品有什么真实优势，再写采购者愿意继续询盘的内容。

本 Skill 只负责生成和修改卖点文案，不生成标题，不读取或改写其他商品，不批量写入国际站后台。

## 核心原则

- 只写已确认事实。不得编造材质、规格、性能、认证、MOQ、交期、产能、工厂面积、客户案例或出口市场。
- 不做通用空话。每条 Sell Point 都要回答一个采购问题，并尽量包含具体产品事实或商家能力。
- 读取商家画像后再写。用 `USER.md` 理解公司和客户背景，用 `IDENTITY.md` 理解品牌身份，用 `SOUL.md` 对齐语气；这些文件缺失时继续执行，不假装已读取。
- 当前对话中的最新事实优先于画像文件。画像与用户本次输入冲突时，使用 `ask_user` 确认，不自行选择。
- 搜索结果只用于发现行业采购关注点、常见参数维度和应用场景。它不能证明该商家具备对应能力。
- 默认输出英文，可按用户要求附中文释义；最终可复制区始终保留正好 5 条英文 Sell Point。

## 可使用的能力

| 能力 | 用途 | 边界 |
|---|---|---|
| 读取 `USER.md` | 获取公司类型、主营产品、目标客户、市场、真实业务能力和偏好。 | 只使用文件中明确写出的事实；陈旧或冲突内容需确认。 |
| 读取 `IDENTITY.md` | 获取品牌名称、角色身份和对外定位。 | 不从品牌定位推导未写明的认证、规模或能力。 |
| 读取 `SOUL.md` | 对齐正式、专业、简洁、技术型或服务型等表达风格。 | 只控制语气，不把人格描述当产品事实。 |
| `ask_user` | 补齐会改变卖点内容的产品、定制、工厂、质量和交付信息。 | 已有信息不重复问；每轮聚焦一个主题，最多 3 轮。 |
| `web_search` | 调研该产品的 B2B 买家关注点、关键参数、应用和常见定制方向。 | 搜索内容标记为行业线索，仅用于提问和选维度。 |

## 执行流程

### 1. 建立商家与产品上下文

先读取当前 Agent 上下文中可访问的 `USER.md`、`IDENTITY.md`、`SOUL.md`，整理：

- 商家是工厂、工贸一体、贸易商还是品牌商。
- 主营产品、目标客户、目标市场和常见订单类型。
- 已确认的 OEM/ODM、Logo、包装、颜色、尺寸、打样、质检和交付能力。
- 品牌定位和对外语气。

再提取用户本次输入中的产品名、产品资料和特别要求。不要要求用户提供商品 ID。

### 2. 判断信息是否够写

至少需要确认产品是什么。以下信息能显著提高质量：

- 核心亮点：最主要卖点、创新点或差异化特性。
- 功能用途：关键功能、实用性和能带来的利益。
- 主要属性：材质、规格、尺寸、容量、重量或兼容性。
- 场景体验：适用范围、目标客户、便捷性和体验优势。
- 配件与支持：随附配件、操作说明、使用支持或服务渠道；不承诺未确认的售后和保修。
- 可选商家优势：定制、制造、质检、包装、样品和交付能力，可在用户指定时替换或强化默认维度。

用户只给产品名时，不要立刻用模板填满。先进入第 3、4 步收集足够事实。

### 3. 调研采购关注点

产品名称明确后，可用 `web_search` 搜索 2-4 组英文查询：

- `<product> B2B buyer key specifications`
- `<product> wholesale buyer concerns`
- `<product> OEM customization options`
- `<product> quality inspection packaging shipping`

只提取“买家通常会问什么”和“应该向用户确认哪些字段”。竞品卖点、行业常见认证和常见工厂能力不得直接写入最终文案。

### 4. 使用 `ask_user` 补关键细节

按信息缺口提问，不照表全问。最多 3 轮，每轮只聚焦一个主题，并给出 2-4 个便于选择的方向：

1. 产品内容：核心亮点、重要功能、材质、规格、尺寸、容量或兼容性。
2. 使用内容：目标买家、适用场景、体验优势、随附配件、操作方式和可证明的支持渠道。
3. 可选商家优势：Logo/包装/颜色/尺寸定制、OEM/ODM、制造质检、MOQ/样品和交付配合。

用户可以指定 5 条卖点的维度。用户未指定时使用默认五维模板；某个默认维度没有真实事实时，用更有证据的产品或应用维度替换，不要用空话凑数。

### 5. 建立事实账本

生成前把信息分为：

| 类型 | 用法 |
|---|---|
| 用户本次确认 | 可直接写入。 |
| `USER.md` / `IDENTITY.md` 中明确事实 | 与本次产品相关且无冲突时可写入。 |
| `SOUL.md` 风格 | 只用于语气。 |
| 公开搜索线索 | 只能用于选择维度或继续提问。 |
| 未确认 | 不写数字或确定性能力；必要时改为中性表达或继续询问。 |

不得用“行业通常如此”替代商家事实。

### 6. 选择五个卖点维度

用户未指定时读取 [selling-point-template.md](references/selling-point-template.md)，使用以下默认顺序：

1. 产品核心亮点：突出最主要卖点或创新点，传递核心价值。
2. 重要功能或特性：说明关键功能、用途、实用性和利益。
3. 材质、规格、尺寸等：自然描述主要属性，让顾客判断是否匹配需求。
4. 场景适用与用户体验：说明适用人群或场合，以及便捷性和体验优势。
5. 配件、使用与服务支持：说明随附配件、操作便利性或支持渠道，不承诺未确认的售后与保修。

以上是默认格式。用户明确指定维度，或产品确实没有配件/服务信息时，可以用已确认的定制、工厂、质量或交付优势替换，但必须告诉用户本次替换了哪个默认维度。维度要根据行业调整，例如零部件强化规格适配，纺织品强化材质工艺，设备强化性能和维护。

### 7. 写出正好五条英文 Sell Point

每条使用以下格式：

```text
Short Heading: Buyer-focused sentence supported by confirmed facts.
```

写作要求：

- 正好 5 条，每条只承担一个主要主题。
- 标题短、内容具体、语言自然，面向 B2B 采购者。
- 优先写“产品事实 → 买家价值”，不要堆形容词。
- 不使用 `best`、`top`、`perfect`、`No.1`、`guaranteed` 等绝对化词语。
- 不写未经确认的品牌、认证、专利、客户名称、市场地位或性能数字。
- 五条之间不重复同一个信息，不把公司简介拆成五句。
- 不输出标题建议、关键词表、商品 ID、差异化策略或后台写入步骤。

### 8. 输出与迭代

先给一行“本次采用的五个维度”，再提供可直接复制的英文内容：

```markdown
采用维度：核心亮点 / 功能特性 / 材质规格 / 场景体验 / 配件与支持

1. **<Short Heading>:** <English selling point>
2. **<Short Heading>:** <English selling point>
3. **<Short Heading>:** <English selling point>
4. **<Short Heading>:** <English selling point>
5. **<Short Heading>:** <English selling point>
```

如果某些维度缺乏事实，在结果后单独列出“待确认信息”，不要把占位符写进五条正式卖点。用户要求修改时，只调整点名的条目或维度，仍保持总数为 5。

## 禁止动作

- 不要求源商品、目标商品 ID 或多个 Listing。
- 不生成或改写商品标题。
- 不调用商品读取、风控词查询或商品批量编辑工具。
- 不执行任何后台写入、发布或覆盖操作。
- 不为了显得专业而编造工厂、定制、认证、MOQ、交期或产能。
- 不照抄公开网页或竞争对手卖点；只吸收通用采购问题后原创表达。

## 质量检查

交付前逐项确认：

- [ ] 最终英文 Sell Point 正好 5 条。
- [ ] 五条默认对应核心亮点、功能特性、材质规格、场景体验、配件与支持；若有替换，已说明替换原因。
- [ ] 所有产品、定制、工厂和服务能力都有事实依据。
- [ ] 每条都回答了不同的采购问题，并说明买家价值。
- [ ] 已读取可访问的 `USER.md`、`IDENTITY.md`、`SOUL.md`，或明确识别为不可用。
- [ ] 搜索线索没有被冒充为商家事实。
- [ ] 没有标题、商品 ID、多 Listing 差异化和后台写入流程。
- [ ] 没有绝对化承诺、竞品品牌或虚构数字。
