# 客户来访接待

接待的结果不是“客户体验不错”，而是客户关心的问题得到证据回应、合作议题形成结论、双方明确下一步。

## 工具

- `ask_user`：确认客户、来访人员与职位、目的、日期、时长、语言、饮食/无障碍、保密、验厂和谈判目标。
- `list`、`read`：读取客户资料、沟通记录、公司介绍、产品、证书、样品、会议室和人员安排。
- `web_search`、`web_fetch`：按需核对客户官网、公开业务、文化与节日注意事项。
- Browser：公开页面依赖脚本渲染时使用。
- `write`、`bash`、`process`、`present_files`：生成接待执行表格。

## 工作流

1. 明确来访类型：初次建立信任、产品验证、验厂、问题解决、年度合作、代理谈判或管理层会晤。
2. 建立客户关注清单：产品、质量、产能、交期、认证、研发、定制、供应链、售后、价格或合作机制；每项匹配真实证据和展示负责人。
3. 设计有时间边界的日程：迎接、人员介绍、公司/产品、参观、样品/测试、合作议题、问题讨论、总结和下一步。
4. 对展厅、车间、实验室和文件设参观边界；涉及其他客户、机密工艺、员工隐私和拍照录像时必须先确认。
5. 明确主接待、主讲、翻译、技术、质量、记录、后勤和决策角色；关键问题不能现场互相推诿。
6. 会后当天整理已确认事项、客户问题、我方承诺、审批项、资料/样品和下次节点。

详细清单见 `references/method.md`。

## 表格交付

生成 `客户来访接待方案_<客户>_<日期>.xlsx`：

| Sheet | 内容 |
|---|---|
| `接待总览` | 目标、人员、日期、语言、文化/饮食、保密和关键结果。 |
| `日程流程` | 时间、环节、目的、负责人、地点、材料和缓冲。 |
| `展示证据` | 客户问题、证据、展示方式、负责人和缺口。 |
| `会议议题` | 议题、问题、我方边界、需决策人和预期结论。 |
| `责任分工` | 接待、主讲、技术、质量、记录、后勤和应急职责。 |
| `风险与确认` | 保密、拍摄、食物、参观、安全、合同和审批项。 |
| `会后动作` | 承诺、负责人、截止时间、交付物和下一节点。 |

```bash
python3 scripts/build_workbook.py --input reception.json \
  --output outputs/客户来访接待方案_<客户>_<日期>.xlsx \
  --expected-sheets '接待总览,日程流程,展示证据,会议议题,责任分工,风险与确认,会后动作'
```

## 边界

- 不编造访客身份、饮食偏好、采购目标、日程确认、公司能力或认证。
- 不自动发送邀请、订车、订酒店、订餐、付款或修改日历。
- 不暴露其他客户、敏感工艺、员工个人信息或未批准区域。
- 报价、折扣、付款、独家权和合同条款必须由授权人确认。
