# YouTube 客户开发

YouTube 账号只是线索入口，不等于采购方。必须通过频道简介、视频内容、官网和公开公司信息判断主体与业务角色；证据不足时写“无法判断”。

## 工具

- `ask_user`：确认产品、目标客户类型、国家/语言、数量、最低证据标准和排除项。
- `web_search`、`web_fetch`：搜索公开频道、视频、官网和公司页，保留来源 URL 与检索日期。
- Browser：查看脚本渲染的公开频道或视频页；不绕过登录、验证码或访问限制。
- `list`、`read`：读取用户产品资料、已有名单和排除名单。
- `write`、`bash`、`process`、`present_files`：去重、生成并校验表格。

## 搜索与核验

1. 组合产品词、应用场景、客户类型、国家和语言词，搜索频道/视频与站外官网。
2. 只保留至少有两类证据的候选：YouTube 内容匹配、频道主体信息、官网业务、公开联系方式、公司注册/行业目录等。
3. 区分品牌方、制造商、进口商、经销商、零售商、服务商、媒体/测评和个人创作者。无法确认采购角色时不得强行归为买家。
4. 联系方式只记录公开业务联系方式和对应来源；不猜邮箱格式，不采集私人敏感信息。
5. 对同一公司多频道、同一频道多视频做公司级去重，同时保留最强证据。
6. 根据产品匹配、主体可信度、渠道/采购线索、地区匹配和联系方式完整度排序；评分规则写入表格。

搜索词与证据检查见 `references/method.md`。

## 表格交付

生成 `YouTube客户开发名单_<产品>_<国家>_<日期>.xlsx`：

| Sheet | 内容 |
|---|---|
| `开发名单` | 优先级、公司/频道、国家、客户类型、匹配点、联系方式和来源。 |
| `账号画像` | 频道主题、代表视频、受众/渠道线索、官网和主体判断。 |
| `网页证据` | URL、页面类型、事实摘要、检索日期和证据强度。 |
| `搜索记录` | 搜索词、范围、结果数、保留数和排除原因。 |
| `风险待确认` | 角色不明、联系方式不明、近期活跃度不足和重复候选。 |
| `开发建议` | 每个优先客户的切入点、证据和首个低门槛行动。 |

```bash
python3 scripts/build_workbook.py --input youtube_leads.json \
  --output outputs/YouTube客户开发名单_<产品>_<国家>_<日期>.xlsx \
  --expected-sheets '开发名单,账号画像,网页证据,搜索记录,风险待确认,开发建议'
```

## 边界

- 不把订阅量、播放量直接当采购能力；不编造进口记录、联系人、邮箱或公司规模。
- 不自动订阅、评论、私信、发邮件或上传内容。
- 不绕过 YouTube/Google 登录、验证码、robots 或访问限制。
- 名单仅用于业务初筛，发送前由用户复核当地隐私、营销和平台规则。
