# 邮件营销配图

邮件配图的任务是帮助收件人更快理解本封邮件的一个核心信息，并把注意力引向一个行动目标。它不能替代邮件正文，也不应堆满卖点、按钮和小字。

## 输入确认

读取邮件草稿、客户/客群、产品资料、Logo、品牌色、产品图和历史视觉。缺少关键内容时，用 `ask_user` 确认：

- 邮件类型：首次开发、跟进、激活、产品发布、展会邀请、节日问候或售后通知；
- 收件人和本封邮件唯一 CTA；
- 主题、核心信息、需要出现的产品与证据；
- 邮件系统建议尺寸、桌面/移动端、语言和文件限制；
- 必须保留或禁止使用的 Logo、颜色、人物、价格和促销信息。

## 视觉策略

1. 一封邮件只围绕一个视觉任务：建立场景、突出新品、解释价值、邀请参加、提醒节点或恢复关系。
2. 默认优先做轻量横版头图或单张内容图；关键信息必须在图片关闭时仍能由正文表达。
3. 文案控制为一句主标题和必要的短副标题。正式 CTA 保留为邮件中的 HTML/文本链接，图片上的按钮只作视觉提示，不能成为唯一入口。
4. 为移动端保留安全区，避免把产品、Logo、日期、地点和重要文字贴近裁切边缘。
5. 价格、折扣、截止日期、库存、客户评价、认证和活动信息必须来自用户材料并逐项核对。

## 工具与生成

- 用 `see_image` 检查产品图、Logo、旧邮件图和参考风格。
- 有产品、包装、人物或品牌参考图时，使用 `image_edit` 并把必要素材放入 `reference_images`；保持产品身份、Logo 和批准文字不变。
- 没有需要保持一致的主体时，才用 `image_generate` 创建抽象背景或纯概念视觉。
- 需要当前节日、展会或公开市场语境时，用 `web_search`、`web_fetch` 核对来源与日期。
- 生成前展示用途、尺寸、文案、素材、版本数和预计调用次数，用户确认后再调用图片工具。

生成后用 `see_image` 复检：移动端缩小后的主信息、产品保真、Logo、拼写、日期、价格、裁切、对比度、虚假元素和敏感素材。发现问题时只定向编辑当前版本。

## 交付

每个版本交付：图片、推荐文件名、用途、建议宽高比、替代文字 `alt text`、对应邮件段落、CTA 文案、事实依据和待确认项。若用户需要多个版本，明确每个版本测试的变量，避免同时改变标题、产品、颜色和 CTA 导致无法比较。

## 边界

- 不自动发送邮件、创建群发、上传到邮件系统或修改客户名单。
- 不在图片里伪造回复率、销量、折扣、稀缺、客户背书或认证。
- 不用像素追踪、隐藏文字、诱导点击或冒充私人往来。
- 用户发送前必须确认收件人范围、文案、图片、链接、附件和当地营销合规。
