# 产品营销策划

从产品事实出发，先决定服务哪类客户和解决什么采购问题，再选择营销内容与优惠机制。不要把一套促销复制给所有客户。

## 工具

- `ask_user`：确认产品、目标客户、市场、营销目标、毛利/预算、产能、交期、认证、案例和不可承诺项。
- `list`、`read`：读取产品目录、报价、认证、客户反馈、历史营销和销售数据。
- `web_search`、`web_fetch`：查公开买家场景、渠道、竞品表达、节日和市场变化，保留来源与日期。
- Browser：核对脚本渲染的公开网页。
- `write`、`bash`、`process`、`present_files`：生成策划表格。

## 工作流

1. 建立“可证明事实”：规格、用途、产能、交期、MOQ、认证、定制、售后和真实案例。缺失项不能改写成卖点。
2. 按客户业务模式、采购阶段、痛点、风险和决策角色分层，不只按国家分组。
3. 为每层客户写一条价值主线：客户问题 → 我方证据 → 可获得结果 → 低门槛下一步。
4. 设计不超过 3 个营销方案方向：价值证明、试单降低风险、复购/年度合作。折扣、返利、赠品、样品和服务必须计算成本并经用户确认。
5. 将方案落到渠道、内容、销售动作、所需素材、负责人/确认人和复查指标。
6. 区分品牌内容、产品内容、成交内容和客户激活内容，避免全部变成打折消息。

方法清单见 `references/method.md`。

## 表格交付

生成 `产品营销方案_<产品>_<日期>.xlsx`：

| Sheet | 内容 |
|---|---|
| `经营结论` | 主客群、主价值、主方案、暂不做事项。 |
| `客户分层` | 客群、采购场景、痛点、证据需求、推进目标。 |
| `价值主张` | 产品事实、客户价值、证据、禁用表达。 |
| `营销方案` | 方案、适用客群、机制、成本、条件、风险和审批。 |
| `内容计划` | 渠道、主题、素材、行动语、责任人和日期。 |
| `行动与复盘` | 动作、指标、周期、停止条件和数据缺口。 |

```bash
python3 scripts/build_workbook.py --input marketing.json \
  --output outputs/产品营销方案_<产品>_<日期>.xlsx \
  --expected-sheets '经营结论,客户分层,价值主张,营销方案,内容计划,行动与复盘'
```

## 边界

- 不编造客户、案例、认证、效果数字、市场份额、库存、交期或负责人。
- 不自动发邮件、发社媒、创建广告、改价、发优惠或修改客户记录。
- 公开竞品信息只用于比较表达与市场线索，不复制对方文案或素材。
- 所有优惠、返点、独家权和付款条件均标“需用户确认/审批”。
