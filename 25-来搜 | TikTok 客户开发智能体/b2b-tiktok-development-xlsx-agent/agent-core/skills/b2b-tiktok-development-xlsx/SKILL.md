# TikTok 客户开发

TikTok 内容可反映产品与渠道兴趣，但账号热度不等于采购能力。先识别账号属于公司、门店、经销商、服务商、创作者还是无法判断，再决定开发价值。

## 工具

- `ask_user`：确认产品、客户类型、国家/语言、数量、合作目标和排除项。
- `web_search`、`web_fetch`：搜索公开账号、视频、官网和公司信息，保留来源和日期。
- Browser：查看公开但依赖脚本渲染的页面；遇到登录、验证码或限制立即停止。
- `list`、`read`：读取产品资料、已有名单和排除名单。
- `write`、`bash`、`process`、`present_files`：去重、生成并校验表格。

## 搜索与核验

1. 按产品、场景、国家、语言、客户角色和相关标签构造多组搜索词。
2. 记录账号主页、代表视频、简介链接、官网和公开联系方式；不把搜索摘要当最终证据。
3. 至少用两类证据确认业务主体。仅有短视频内容而无公司连接时，标“创作者/主体待核验”。
4. 区分销售线索和内容合作线索：品牌/门店/经销商偏销售开发，行业创作者偏内容合作，不能混用评分。
5. 对同一公司多账号、经销商多门店和转载账号做去重，保留原始 URL。
6. 以产品匹配、主体可信度、渠道证据、地区匹配、近期公开活跃和联系方式完整度排序。

方法见 `references/method.md`。

## 表格交付

生成 `TikTok客户开发名单_<产品>_<国家>_<日期>.xlsx`：

| Sheet | 内容 |
|---|---|
| `开发名单` | 优先级、公司/账号、国家、线索类型、匹配点、联系方式和来源。 |
| `账号画像` | 内容主题、代表视频、账号主体、受众/渠道线索和官网。 |
| `网页证据` | URL、页面类型、事实摘要、检索日期和证据强度。 |
| `搜索记录` | 搜索词、范围、结果数、保留数和排除原因。 |
| `风险待确认` | 主体不明、角色不明、联系方式不明和重复候选。 |
| `开发建议` | 销售开发或内容合作切入点、证据和下一步。 |

```bash
python3 scripts/build_workbook.py --input tiktok_leads.json \
  --output outputs/TikTok客户开发名单_<产品>_<国家>_<日期>.xlsx \
  --expected-sheets '开发名单,账号画像,网页证据,搜索记录,风险待确认,开发建议'
```

## 边界

- 不编造粉丝、播放、采购、进口、联系人、邮箱或公司规模。
- 不自动关注、点赞、评论、私信、发邮件或发布内容。
- 不绕过登录、验证码、robots、地区限制或平台访问控制。
- 发送前由用户复核账号身份、商业用途和当地隐私/营销规则。
