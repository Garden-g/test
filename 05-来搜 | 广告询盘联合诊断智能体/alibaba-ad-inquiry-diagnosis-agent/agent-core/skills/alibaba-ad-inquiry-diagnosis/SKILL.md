# 广告与询盘联合诊断

把广告端和询盘端放在同一条证据链里，回答“钱花在哪里、带来什么买家、为什么没有继续转化、下一步由谁处理”。本 Skill 只做联合诊断，不替代完整广告控制台或询盘管理会。

## 执行

1. 确认诊断周期、账户范围、重点计划或商品；未指定时用最近 7 天，并注明时区和数据截止时间。
2. 先发现当前工具及 schema，再只读获取广告账户、计划、商品和报表数据。优先使用 `icbu_ads_account_diagnosis`、`icbu_ads_entity`、`icbu_ads_report_load_datasource`、`icbu_ads_report_execute_sql`。
3. 获取同周期业务员接待与质检数据。优先使用 `subaccount_query`、`query_seller_acct_dim_diag_data`、`query_seller_shop_dim_diag_data`、`query_seller_chat_quality_check_detail`；只对重点线索补 `query_recent_conversation` 与 `query_conversation_msg`。
4. 统一日期、对象和指标定义后再关联广告与询盘。无法用稳定标识直接归因时，只写账户级或商品级相关性，不声称某条询盘来自某个计划。
5. 按“流量获取 → 商品承接 → 询盘质量 → 首响与追问 → 报价/样品/下次节点”定位断点，并将原因标为高、中、低置信度。
6. 输出 `广告询盘联合诊断_<周期>.xlsx`，至少包含 `经营结论`、`转化断点`、`重点线索`、`行动与复查`。每个动作写负责人、对象、完成口径、截止或复查时间。

## 判断边界

- 广告和询盘数据周期、范围或汇总口径不一致时，结论标记“口径冲突待核验”，不计算精确归因或预算调整值。
- 报表零行只表示当前查询未返回记录，不等于没有消耗或没有询盘。
- 不编造订单归因、客户意图、业务员责任、ROI、行业阈值或因果关系。
- 暂停计划、调预算/出价、修改商品、发送消息、分配客户或更新跟进状态都必须另行展示具体对象与影响，并获得用户明确确认；本次默认不执行。
