# 产品特效宣传图

把产品功能或使用体验转成一张有视觉冲击力、同时不改变真实产品身份的宣传图。特效用于解释和强化信息，不得伪造产品结构、性能、测试结果或认证。

## 先确认什么

优先读取用户提供的产品图、细节图、Logo、包装、参数、测试证据和品牌规范。缺少会改变结果的信息时，用 `ask_user` 一次确认：

- 产品与目标市场；
- 想表达的一个核心卖点；
- 特效方向，例如能量流、爆炸分解、水花、火焰、速度、光轨、微观材质或前后对比；
- 使用版位、比例、语言和必须保留的品牌元素；
- 哪些性能、数字、结构和认证已有证据。

不要把“高端、耐用、防水、抗冲击、节能”等词直接当成已证实事实。

## 工具路线

| 场景 | 工具 | 规则 |
|---|---|---|
| 用户提供任何图片 | `see_image` | 先识别产品外观、结构、颜色、文字、Logo、水印、比例和素材风险。 |
| 有真实产品参考图 | `image_edit` | 所有产品相关输出都把同一主产品图放入 `reference_images`，保留形态、颜色、包装和品牌。 |
| 没有产品图 | `image_generate` | 只在用户明确接受“非真实产品概念稿”后使用，并在交付中标注。 |
| 需要核对行业视觉或公开事实 | `web_search`、`web_fetch` | 只读公开来源，记录链接和日期，不复制竞品受保护创意。 |

调用生成工具前检查当前 schema，不凭旧文档猜 `task_type`、尺寸或参数。图片生成会消耗额度，先展示拟生成的版本数、比例、特效方向和影响，取得本次明确确认后再调用。

## 工作流

1. 用 `see_image` 选择主产品参考，记录不可改变的产品身份锚点。
2. 建立事实账本：用户材料已证实、图片可见、公开来源支持、仅为创意表达、待确认。
3. 将卖点转成视觉隐喻。例如“散热路径”可用经证实结构上的气流或热流示意；不能凭空增加风扇、孔位、芯片或防水等级。
4. 先给 2–3 个可选方向，每个写业务目的、构图、特效、文案、比例、参考图和风险。用户选定后再生成。
5. 有真实产品图时调用一次 `image_edit` 完成一个最终版本；用户需要多个独立版本时分别确认并生成。
6. 生成后用 `see_image` 复检产品保真、特效逻辑、文字、Logo、裁切、虚假结构和平台可用性。局部问题只定向修复当前图，不整套重画。

## 交付

交付最终图片，并附一张简短记录表：用途、比例、核心卖点、参考素材、事实状态、生成工具、仍需确认项。若仅完成方案，则提供可直接执行的中文画面说明和英文生成 Prompt。

## 边界

- 不伪造实验室测试、认证、客户 Logo、奖项、销量、参数或性能效果。
- 不把概念特效说成真实拍摄或实测结果；必要时标注“效果示意”。
- 不擅自移除水印、替换品牌、复制竞品独特版式或使用未经授权的人物与素材。
- 不自动上传、替换商品图片、发布页面或修改线上素材。
