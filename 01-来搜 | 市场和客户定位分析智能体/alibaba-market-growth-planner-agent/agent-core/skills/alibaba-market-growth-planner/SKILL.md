# 市场增长规划

本 Skill 属于业务策划，不深入调用店铺私域工具。用户有店铺数据时读取其导出文件；没有时用公开网络证据和用户事实做初步判断，并明确“仅覆盖公开信息”。

## 工具

| 工具 | 用途 | 边界 |
|---|---|---|
| `ask_user` | 确认产品、目标客户、已有市场、候选国家、预算/资源和本期目标。 | 一次最多问 3 组关键问题。 |
| `list`、`read` | 读取用户提供的国家流量、询盘、成交、客户、商品、广告导出表以及品牌资料。 | 不把缺失值补成 0。 |
| `web_search`、`web_fetch` | 查公开市场需求、渠道、法规/认证入口、竞争格局、节日和买家行为。 | 保留来源与日期；事实和推断分开。 |
| Browser | 网页依赖脚本渲染、搜索摘要不足或需要核对原页面时。 | 只读公开页面，不绕过登录或访问限制。 |
| `write`、`bash`、`process`、`present_files` | 准备数据、生成并校验表格、交付文件。 | 不执行后台变更。 |

## 输入

至少确认：产品与关键认证、目标客户类型、现有强势国家、候选国家、本期目标、可投入销售/内容/广告资源。若用户要求基于店铺实际表现判断，还要其提供相应导出表；不能用公开搜索替代私域经营数据。

## 分析框架

1. 建立基线：现有国家的流量、询盘、成交、客单、复购、毛利、交付和售后能力。缺哪个就标缺口。
2. 对候选市场从四个维度比较：
   - 市场吸引力：公开需求、渠道成熟度、进口/采购信号。
   - 产品适配：规格、价格带、认证、语言、使用场景和交付条件。
   - 进入难度：竞争、法规、认证、物流、付款、售后和本地关系。
   - 企业承接：现有客户证据、素材、销售语言、响应能力和预算。
3. 使用 P0/P1/P2/观察池分级。分级依据必须在表中可追溯；无数据时不能给精确分数。
4. 对 P0/P1 市场分别制定商品、内容、询盘承接、渠道和销售动作；广告预算调整只列为待确认建议。
5. 设定 30/60/90 天验证节点、成功指标、停止条件和补数动作。

按需读取 `references/market_priority.md` 与 `references/region_localization.md`，其中的阈值仅作方法参考，必须按企业历史或用户确认校准。

## 表格交付

生成 `市场增长规划_<YYYY-MM-DD>.xlsx`：

| Sheet | 内容 |
|---|---|
| `老板结论` | P0/P1 市场、暂缓市场、资源取舍和首要行动。 |
| `市场证据` | 用户数据、公开来源、日期、事实摘要和证据强度。 |
| `市场评分` | 吸引力、产品适配、进入难度、企业承接及分级。 |
| `本地化缺口` | 商品、语言、素材、认证、交付和销售承接缺口。 |
| `行动路线` | 30/60/90 天动作、负责人/确认人、指标和停止条件。 |
| `数据缺口` | 未返回、不可判断、仅公开信息及补数方式。 |

```bash
python3 scripts/build_workbook.py \
  --input market.json \
  --output outputs/市场增长规划_<YYYY-MM-DD>.xlsx \
  --expected-sheets '老板结论,市场证据,市场评分,本地化缺口,行动路线,数据缺口'
```

交付前回读并确认 6 个 sheet、无公式、无 Excel Table、无 drawing。

## 禁止事项

- 不编造市场规模、采购量、转化率、客户、认证要求、预算、负责人或店铺后台数据。
- 不把公开搜索的行业信息写成该店铺已经取得的经营成绩。
- 不直接改广告预算、投放国家、商品、页面或销售分配。
- 法规、认证、税务和合同信息只做线索，重要决策应由当地专业人士复核。
